打开 http://127.0.0.1:4183/ 。可以用下列只读请求确认启动的是融合服务，返回应含 `schemaVersion:17`：

这里仅给出启动方式，本次没有自动启动第二个长期服务。端口若占用，换空闲端口并在页面/接入配置中保持一致，不结束未知进程。`--proxy-port`是CLI启动参数；在Web新建接入配置时仍需明确填 **7789**，不要假定表单默认值已随CLI自动改变。

## 建议手测顺序

1. 打开代理视图的“Agent 接入配置”，填写Agent、项目绝对路径和7789端口，保存并生成启动命令。先看诊断；开启监听后没有请求时应显示“等待流量”，不是“Agent接入成功”。
2. 在自己的终端运行页面生成的命令，显式启动一个新Agent，再发一个简短请求。现有已启动Agent不会被自动接管。不要禁用TLS校验或随意安装全局CA；启动器采用子进程范围的代理和信任。真实模型调用可能产生费用，由你自己决定是否执行。
3. 请求结束后看观察/在途/待落盘/已保存计数和列表更新。进入详情检查请求、响应、headers、模型、提示词、tools、usage、结束原因与错误。检查“网络终态”“解析任务结果”“原文完整性”分别显示，不能互相冒充。
4. 打开协议分析和Context Diff，检查中文、结构化内容、工具参数和多轮上下文。Diff的默认比较有明确关联依据；没有可证明的上一轮时允许未知或显式选对象，不按同模型/相邻时间擅自串会话。
5. 下载请求/响应原文，按自己发送的内容检查无脱敏；压缩原文是编码字节，正文视图是解码结果。语义分析有独立2MiB上限，不等于原文也只有2MiB。原文默认每方向100MiB、合计10GB，出现降级看实际状态，不人为造满额。开发者可对同一下载地址发送 `Range: bytes=0-63` 读取64字节（不足则读到末尾），返回206和精确Content-Range；`x-capture-sha256`仍是整份已保存原文的摘要，不是该分段摘要。
6. 到关联证据入口查看已有原生ID、直接/候选关系及确认/撤销；缺少Agent来源ID时保持未关联，不以“必须有边”判定抓包失败。
7. 取消一次请求或停止监控，观察中断/不完整原因，再正常开启一次。停止共享代理可能影响仍在用它的Agent；Agent退出不等于共享代理自动停止。结束时先停止监控，再在服务终端按Ctrl+C等待退出。

可选：只读查看容量抽屉；正文删除是有确认的不可逆操作，基础手测无需执行。不要用删除DB/WAL、原文或scan数据的方式复位，也不要清理之前其他任务的数据。

详情中的采集元数据/协议分析读取失败或5秒超时后，现在有独立重试按钮；只重读本地接口，不重发模型请求。协议分析仍按需打开，切换语言不重查，已删除正文不会因重试恢复。实际模型取消/超时和本地详情读取超时是不同问题。

所有监控原文可能含凭据、prompt和源码，无脱敏；请保管上述本地目录，不要把原文或完整headers贴进反馈/提交。
