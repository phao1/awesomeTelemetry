## Capture policy

Store and display observed request/response headers, URL, body, prompt, public reasoning and tool data without masking or rewriting. Forwarding must preserve the original bytes. Avoid echoing captured data into application logs or test output. CA private keys are application infrastructure and are not capture payload.

Original body files are immutable after completion; 10 GB means 10,000,000,000 bytes by default, configurable. Per-direction default limit is 100 MiB (104,857,600 bytes), configurable. A global 32 MiB pending write budget bounds memory. Limits stop new collection and expose explicit status; existing files are never automatically evicted to make space. Default capture retention has no automatic expiry. Manual deletion/export remains explicit.

SQLite metadata and bounded previews retain the existing <200MB DB+WAL and <20MB WAL budget. Original files have their separate disk budget. A 2MiB context-diff analysis limit is not a body capture limit. Large originals remain downloadable even when semantic analysis declines them.
