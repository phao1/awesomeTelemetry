## Why

The application has substantial capture and analysis capabilities, but its fragmented controls, weak visual hierarchy, misleading labels and difficult evidence navigation make those capabilities hard to use. Refresh the whole frontend on an isolated branch based on the fusion working snapshot, using real investigation workflows and reference products rather than a cosmetic skin.

## What Changes

- Establish a coherent desktop workbench: clear navigation, visible search, consistent toolbars, readable surfaces, light/dark themes, accessible interaction states and purposeful reduced-motion-aware animation.
- Improve every existing area: session discovery/trajectory/inspector, Agent overview, run/call comparison, live capture/setup/import, advanced Frida capture, Mission dashboards and Agent Team inspection.
- Prioritize problem-to-evidence workflows: locate errors/slow operations, inspect input/output, understand meaningful differences, and trace observed team relationships without inventing communication or correctness.
- Preserve paging, virtualization, lazy body reads, existing URL identities, local-only controls and backend contracts. No new runtime dependency, animation framework, router or synthetic certification of Agent support.
- Verify real rendered behavior, keyboard access, themes, responsive widths, request counts and existing performance budgets; retain incomplete areas in an explicit checklist.
- User amendment 2026-10-18: remove money/currency-based presentation across views and generated reports; keep Token/cache/call observations and preserve original evidence without API/DB deletion or new currency fields.

## Capabilities

### New Capabilities

- `observability-workbench`: cross-feature investigation workflows, coherent presentation and evidence-first frontend acceptance.

### Modified Capabilities

None initially. Existing frontend/design-system behavior and authoritative contracts remain binding; any necessary change will be explicit rather than hidden in CSS.

## Impact

Frontend components, styles, i18n, view integration and colocated tests. Development receives its own worktree/ports and no copied user credentials or shared writable application DB. Backend behavior and fusion support claims remain unchanged. Exact implementation file whitelists are recorded in design.md before each batch. No commit or push is implied by branch creation.
