# DSH 式轨迹阅读重构

日期：2026 年 10 月 28 日（Pacific/Auckland）。状态：实现和首轮页面验收已完成；提交前全量检查单独记录，不能将局部验收当作全部检查通过。

本次依据用户提供的 DSH 截图和对实际页面的反馈，修订前一版工作台的阅读方式。用户明确要求优先解决“定位图块、看工具记录、看模型思考和输出”的效率，并授权替代之前的双层时间图与成员泳道。本次仍在任务中心及现有三种读法内完成，不另建业务入口。

## 1. 用户打开页面是为了什么

一次调查通常从以下问题开始：

1. 这个任务里，用户提了什么要求，Agent 如何推进，中间调用了什么工具？
2. 某个图块具体对应哪一条记录？工具收到的参数、返回的内容，以及模型公开记录的思考或输出是什么？
3. 多 Agent 中是哪位成员在处理这一步？能否进入该成员后再返回主任务原处？
4. 如果已有抓包，原生日志和实际模型请求之间有哪些可用证据？两次请求的上下文、工具结果、输出、错误和已知网络时间有哪些差异？

图和摘要用于找到这些内容，正文应获得最多的空间。抓包对比可以支持检查实际请求/响应和上下文变化；缺少相同任务、配置和计时依据时，不能自动得出质量更好、推理更快或因果优化成功的结论。请求正文的查看与比较也不应启动另一次模型请求。

## 2. 上一版的问题与这次的取舍

| 上一版问题 | 本次设计 |
|---|---|
| 全范围密度图、局部时间图、活动/成员泳道切换同时出现 | 只保留一张紧凑图，内部仅输入/模型/工具三细行 |
| 几天的完整时间跨度挤压当前页的几分钟活动，色块难以区分 | 默认用当前页记录的等宽顺序，切换“时长”后才使用真实已知区间 |
| 任务头、来源/覆盖、成员范围、模式、回放、筛选、窗口说明各占一行 | 合并横向控制，次要信息收起；它们随主内容滚出 |
| 正文被夹在页面底部的短列表滚动区中 | 任务过程采用一个主滚动根，列表不再拥有一个独立的小高度滚动盒 |
| 检查器窄，默认摘要只有身份和状态，还要再次点正文 | 右侧给足宽度并允许拖动；默认摘要直接读可用参数/结果或公开思考/输出 |
| 分组头和内部 ID 比实际记录更抢眼 | 连续紧凑记录行为主，类型/成员/轮次保留，原始身份在详情中可查 |

这里的“一个图”不表示把不同类型都涂成同一根条；DSH 截图本身也是输入、模型、工具三细行。它们构成同一个定位组件，不再追加第二图或按成员拆成多张图。

## 4. 单图、当前页和全任务范围

图中的每个可选块都对应已经加载的原始记录，当前页最多 200 条。工具调用与结果可能是两条原始记录；展示时可以按精确身份组织，但不得凭名字、时间相近或邻接合成一次执行，也不得丢失原始记录选择入口。

图和列表共用当前页。页面明确展示“当前页范围 / 记录总数”，翻页保持既有固定窗口版本。默认等宽横轴表达阅读顺序，不代表耗时；已知真实日志时长可切换查看，未知时长仍为开始标记并显示未记录。图不生成 TTFT、隐藏思考或解码计时。

后端既有两次范围读取继续保留：

- `/api/tasks/:id/records` 提供当前有界元数据及结构。
- `/api/tasks/:id/timeline` 提供该固定窗口的全范围起止、记录总数和成员覆盖等元数据。

完整范围的 160 个密度桶不是原始记录，本次不再将它们绘制成另一张图或伪装成可点击的精确记录。未加载的历史通过明确翻页或既有原始锚点定位读取，不从图上猜一个附近记录作为结果。

缩放、平移和框选都只针对所显示投影。只有真实 UTC 范围能进入现有服务端 `from/to` 筛选；等宽序号不能被转换为虚构时间。过滤不应重新定义原始身份，选中块时先展开必要祖先，再滚到对应行；键盘和鼠标选择应指向同一记录。

主会话、全任务、所选成员仍由外层范围选择。全任务记录必须显示成员身份，并保留每个成员自己的原生顺序和轮次边界，不能将并行成员拼成单段对话或编造跨成员因果顺序。

## 5. 连续滚动和吸顶布局

任务过程 `.task-process` 是正文的主纵向滚动根。任务列表保留独立选择职责，不让记录区域再嵌套一个只能看到两三行的小滚动列表。虚拟列表仍保留，并使用这个主滚动根计算位置与可见范围。

| 页面部分 | 滚动行为 |
|---|---|
| 紧凑任务名 | 在任务过程顶部吸顶，单行省略但可查看完整标题 |
| 来源/时间/覆盖/状态摘要 | 紧凑显示或收起，滚动后让出空间 |
| 主/全任务/成员、三种读法、搜索、错误及次要按钮 | 横排组织，自然滚出，不永久堆在正文上方 |
| 单张轨迹图 | 紧贴任务名下方吸顶，位置使用实际标题高度计算 |
| 轮次/步骤/模型/工具记录 | 在主滚动根中连续阅读并虚拟化；图定位需扣除吸顶高度 |
| 所选记录检查器 | 右侧宽面板，随可视区域吸顶，允许拖宽；窄屏保留可达的关闭/返回 |

目标是滚动后，任务内永久占高的内容只剩任务名与单图。窗口摘要、来源边界、翻页等说明保留，但不持续挤占正文高度。精确定位、折叠展开、切成员和翻页后需要重新测量列表偏移，避免目标被吸顶图遮住或跳到错误记录。

## 6. 点击后直接看到重要正文

连续行使用类型标签、工具名/可用摘要、成员和已知时间帮助扫读。选择记录后打开宽检查器，默认摘要直接显示该记录可用的正文：

- 工具：参数与结果；如果分别保存在两个原始记录里，只使用已有结构提供的精确配对。
- 模型：公开记录的思考/输出及可用输入；没有文本输出时明确提示未提供。
- 用户与上下文：所选原始内容，保留来源和类型，不把上下文当作用户追加要求。
- 错误：保留该条原始错误和所在成员/轮次，不把重试后的成功覆盖为“从未发生错误”。

默认摘要最多读取所选记录及一个有精确同工具身份的配对记录，已读内容按原始身份缓存。没有精确配对、多个冲突配对、缺失/被删除/未加载的内容要明确表示，不自动遍历全部相关事件。展开分组、缩放图、悬停和滚动都不请求正文。

原文、来源和计时保持可单独进入。Raw 只在明确进入原文时读取；它与格式化输入/输出的读取分开。切换记录、成员、任务、关闭面板或来源失效时取消所拥有的请求，晚到结果不能覆盖新的选择。加载、空内容、失败和重试需要各自可辨认。

所有内容都以惰性文本/JSON 展示，不执行捕获的 HTML、代码或工具参数。长正文保留截断说明和显式展开；宽度和文本阅读能力优先于装饰性状态卡片。

## 7. 抓包对比能帮助用户做什么

用户先在原生日志中找到目标工具/模型记录，再按已有明确关联查看对应抓包。可检查：实际模型/端点、请求上下文、工具声明/已观察到的工具返回、公开响应、错误、原始用量和具备依据的网络时间。需要对照两次请求时使用现有明确选对流程，并保留两侧原始来源。

这能帮助用户追查“这次请求为什么多了上下文”“工具返回是否进入下一次请求”“错误来自哪里”“哪些数据没有抓到”。没有网络原文时，只能显示已有日志，不把日志重建内容标成抓包；没有相同身份或完整关联时，展示候选/未知，不擅自合并。

本次不新增自动归因、质量评分、重发请求、自动调参或新的抓包对比引擎，也不声称选择一次记录就能还原 Agent 未记录的全部内部状态。

## 8. 保持不变的边界

- 任务仍以主会话为中心，单 Agent/多 Agent 是同一任务的执行结构。
- 采集与导入保留独立来源、发生/导入时间和原始身份。
- 监控、抓包默认关闭。看页面、读日志、展开正文或回放不会启动监听器、代理、CDP、Frida、外部 Agent 或工具。
- 不改数据库、采集协议、原文存储、后端身份规则或既有导出语义。
- 不增加运行时依赖，不放宽已有断言或性能预算。
- 已有真实数据只用于本机查看验收，不将正文、凭据、数据库或截图中的敏感内容加入版本库。
