# 以任务为中心的遥测工作台重构提案

日期：2026 年 10 月 25 日。状态：任务工作台主流程已实现并进入交付验收；详见 [implementation.md](implementation.md)。

工作台以用户正在完成的任务为中心。任务的执行载体是被监控的主会话；主会话可以独立执行，也可以调用其他 Agent。单 Agent 和多 Agent 因此属于同一个任务的执行方式。它们共享一个任务入口、一个执行上下文和一套回放。

## 产品结构

```text
任务中心
  任务列表
    采集记录
    导入记录
  任务详情
    任务头部摘要与可展开成员结构
    执行过程 默认进入
      范围 主会话 / 全任务 / 指定成员
      读法 对话 / 执行轨迹 / 原始事件
      逐步回放 作为可选操作
    共享证据检查器
    对比 从任务选择中发起

数据接入
  自动采集
    本地会话记录
    网络代理
    CDP
    Frida
    已支持的官方事件
  文件导入
  待关联遥测

设置
```

总览不作为默认一级页面。任务列表只展示有助于操作的摘要，例如正在监控哪些任务、哪些任务有新记录、采集哪里失败。现有统计页面保留兼容入口，后续按实际使用价值收敛。

## 两个核心维度

第一维是用户关注的对象：任务及其主会话、参与 Agent 和执行证据。

第二维是数据进入系统的方式：采集记录或导入记录。本地日志监听、网络代理、CDP、Frida 等属于采集通道，不是新的任务类型。导入文件也可能包含真实发生的执行，因此不能把“导入”解释成“模拟”，也不能把“采集”当成真实性认证。

## 主要改变

- 以主会话为任务锚点，先提供任务读取投影，不先建立完整项目管理系统。
- 单 Agent 和多 Agent 共用任务列表与任务详情；协作结构根据实际证据展开。
- 保留采集与导入两种进入方式，列表可独立查看，记录始终带来源标识。
- 默认直接阅读执行过程，三种读法共享任务、成员与事件身份；回放作为可选操作。
- 过程与原始证据双向定位，支持父子 Agent 往返、历史阅读稳定和锚点恢复。
- 遥测证据明确区分来源、时间、覆盖和关联可信度；未归属的请求进入待关联区。
- 数据接入解释各通道的适用条件，并区分配置、监听、观察到数据和保存成功。
- 保留旧 URL、原始记录和身份；按契约、读取模型、导航、回放和实时状态逐步迁移。

## 范围和边界

本轮已在 `codex/task-observability-workbench` 实施任务读取投影、统一工作台、证据检查器、数据接入和运行开关。之前的本机 Codex 监控改动保留，讨论中的前端原型继续归档。变更保持本地，尚未提交、推送或发布。设计中的增强项逐项保留在验收清单，实际完成范围以交付报告为准。

不通过标题相似或时间相近自动把多个工作目标归成一个任务，不虚构任务指派、通信或父子关系，不把导入副本计为新执行。跨主会话的业务任务归组作为后续独立能力设计。

完整信息架构、数据模型、页面流程和技术边界见 [design.md](design.md)，分阶段实施与验收见 [tasks.md](tasks.md)。

DSH 的源码调研、参考交互与差异化改进见 [dsh-reference.md](dsh-reference.md)。本方案借鉴其会话内轨迹和检查器，进一步设计多来源证据关联、跨成员调查及来源区分。
