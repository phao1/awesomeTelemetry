# Acknowledged mailbox
NewMailbox(sim,lease) with a nonnegative integer virtual lease duration; negative lease panics. No goroutines, real sleeps or randomness. Simulator jobs use buffered channel lanes and Step selects one ready lane deterministically.
Offer(id,body) queues a message unless closed or the ID is already queued/reserved/delivered. It returns true only when accepted. IDs may be reused after acknowledgement, or after a closed mailbox drops them (offers still fail on closed).
Pull returns a buffered receive-only delivery channel and an idempotent cancellation function. No result is published inline. Waiters and messages are FIFO. Matching reserves synchronously, publication is a deferred job.
Cancellation succeeds only before publication, returns a reserved message to the FRONT, publishes nothing, and permits the next live waiter to receive it. Stale delivery jobs cannot revive cancelled waiters. Cancel returns false after publication.
Successful publication returns Delivery{ID,Body,Token,Error:""}. Tokens are unique, monotonically increasing per mailbox; reservations consume tokens even if cancelled. A token is acknowledgeable only after publication. Lease clock starts at publication, not matching.
Ack(token) removes a published lease and frees its ID; Nack(token) requeues its message at the END. Both return true only once for a current published lease. Stale, unknown, reserved and already-settled tokens return false. Expiry acts like Nack. Redelivery always has a fresh token. Lease zero schedules expiry as a separate job after publication.
Close is idempotent. It drops queued messages, turns all unpublished pulls into deferred Delivery{Error:"closed"}, and preserves published leases until Ack/Nack/expiry. Closing never requeues a message. Unpublished closed deliveries are cancellable. Pull after close creates a cancellable deferred closed delivery. No channel is closed; a channel receives at most one value.
Any ready scheduler job may be chosen before another. Ack/Nack/Close/Cancel can be called between any jobs. Message ID ownership must be conserved across every interleaving. Run go test ./... .

Stats returns Counts{Queued,InFlight,Waiting,IDs}: queued messages, reserved-or-published deliveries, unmatched uncancelled pull requests, and currently owned unique message IDs. Counts are observed synchronously, including between scheduler jobs. Closing drops queued/unpublished ID ownership but retains published ownership until it settles. Closed mailboxes never retain requeued messages or IDs of settled deliveries.
