# Inventory journal
Run python3 replay.py for the user's shipment report and python3 -m unittest inventory.test_service for normal workflows. Public entry: inventory.Inventory.
Ingestion accepts dictionaries with id, revision, at, warehouse, sku, quantity; optional unit defaults to each, deleted defaults false. Each and box conversion defaults are one and twelve. Quantities use exact decimal arithmetic and may be zero or negative. All external timestamps are canonicalized to ISO 8601 UTC seconds before grouping by UTC day.
A logical shipment is identified by id. Its highest revision is current regardless of arrival order. The same (id,revision) may replay if its normalized record is identical; a conflicting duplicate aborts the whole ingest. A stale lower revision remains in history but cannot change current reports.
correct(id,quantity=None,warehouse=None,at=None) creates the next revision. Only None means keep the old value; zero quantity and empty warehouse are real corrections. Corrections use base units. delete creates a tombstone revision. Current tombstones do not contribute, and lower revisions cannot resurrect them.
day(day) returns sorted warehouse/sku groups with exact decimal quantity string and record count, including groups whose sum is zero. Group identity is the ordered pair of strings; punctuation is literal and cannot act as a separator. Deleted rows are omitted.
Reports cache day projections, but moving a current record to a different day must invalidate both its former and new day. Stale revisions and identical replays must not change projections. Returned reports are deep copies.
All batch ingestion validates completely before appending. Failed ingestion leaves journal and reports unchanged. checkpoint captures immutable normalized journal rows; restore rebuilds the journal and clears projections. history returns revisions in ascending order.
CSV utilities implement quoted fields through the standard csv module; exports/pivots/reconciliation use exact decimals and preserve warehouse/sku pair identity. Only source changes are allowed. No extra dependencies.
