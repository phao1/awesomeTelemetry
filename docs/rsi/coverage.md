# RSI 功能覆盖清单

对照 [design.md](design.md) 逐项记录现状，数据来自 2026-11-07 的真实运行。优化者和被优化 Agent 用 DeepSeek（`deepseek-flash`），监控用 `gpt-6.1-sol`，运行环境是 M1 8GB 上的 Colima（4 核 4GB）。

状态的含义：

- **真实**：用真实模型和真实容器跑通过，有账本记录。
- **脚本模型**：真实容器、真实服务和真实闸门，但模型回复是脚本化的。
- **仅测试**：只有自动化测试覆盖。
- **未做**：没有实现。

## 明确不在这一版

设计中标为“之后”或“先不做”：

- 云端托管、多租户、额度控制。每个人在自己机器上运行。
- Verified Mini、Multi-SWE-bench 和近千题规模。
- `docker context` 经 ssh 放到另一台机器评测。
- Windows 和 GUI 形态的评测。
- OTLP 采集渠道，设计中是备用项。现在用模型代理和会话库。
- 把 OpenCode 接入 task-health 的富化（`server/task-health/collector.ts` 只支持 codex、claude、codeagent）。

## 已知限制

- **作弊样本是模板**。注入和校准语料证明这几类做法能被拦住，不能证明真实作弊都能被发现。完整校准的高分不能外推到真实攻击，公开研究里监控在 SWE 类任务上只抓到 42%～65%。
- **题库偏容易且风格一致**。OpenCode 加 DeepSeek 在小题集上满分，在完整题集上接近满分，分数提升空间很小。真正优化成熟的 Agent 需要更难的题。
- **分数上涨只在演示 Agent 上验证过**。它是故意削弱的，修的是明显缺陷。
- **候选补丁和隐藏测试在同一个评估容器里运行**，补丁理论上可以影响测试过程。
- **L1 拒绝的类别会告诉优化者**，理论上可以被用来低速试探规则。
- **账本中段被改动，要到 `ledger verify` 或下次重建才发现**。这是为了不在每次读取时重放整个账本。
- **只在 macOS + Colima 上验证过隔离**。
