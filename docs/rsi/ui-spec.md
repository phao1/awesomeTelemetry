# RSI 页面规格（#/rsi）

依据 [界面设计规范](../design/ui-design-system.md)，组件、token、格式规则、质量门槛都沿用它，这里只写 RSI 特有的部分。第 8 节的质量门槛同样适用。接口以 `openspec/contracts/api.md` 和 `openspec/contracts/rsi.md` 为准。

**这个页面要回答的问题：** 分数是不是真的在涨？它改了什么？有没有作弊？现在要我做什么？

**全站规则：**
- 不出现任何金额，只有 token 和缓存命中率。
- 不向用户暴露内部字段名。状态、原因代码都要翻译成人话，中英文都有。
- 封存集和最终留出集的逐题明细只有人看得到，页面可以显示，优化者接口不行。
- 用词：调优任务、迭代、晋级、挂起、封存集、最终留出集、优化者、被优化 Agent、噪声带。

## 1. 导航

侧栏“评测”分组加一项 **自优化**（图标 `sparkles` 或 `git-branch`），路由 `#/rsi`。有待审项时显示计数 Badge。命令面板能搜到“自优化”和“新建调优任务”。

子视图用查询参数，深链刷新可用：

| 视图 | 路由 |
| --- | --- |
| 调优任务列表 | `#/rsi` |
| 待审队列 | `#/rsi?view=review` |
| 监控校准 | `#/rsi?view=calibration&task=<id>` |
| 任务详情 | `#/rsi?task=<id>` |
| 迭代详情 | `#/rsi?task=<id>&iter=<seq>` |

列表页顶部用 underline Tabs 切换：任务 | 待审（计数）| 监控校准。

## 2. 执行器状态（全局）

平台规定只有手动启动的 worker 才能运行代码，所以用户必须一眼看到它在不在跑。

页面头右侧放一个状态药丸：
- 运行中：绿点 + “执行器运行中”，悬停显示当前阶段和心跳时间。
- 未运行：灰点 + “执行器未运行”，点击弹出 Popover：一句解释（“页面操作只会进入队列，执行器启动后才会执行”）+ CopyField 显示启动命令 `node bin/rsi.js worker --execute --watch --task <id>`。

队列里有待执行命令而 worker 没跑时，在任务详情顶部显示 attention Callout。

## 3. 调优任务列表

- 页面头：标题“自优化”+ 计数 Badge；右侧执行器药丸、“新建任务”primary 按钮。
- 表格列：任务（名称 + 12px 元信息：Agent 名 · 优化者名）| 状态 Badge | 迭代（#n）| 待审（>0 时 attention）| 通过数（基线 → 最优，如 `9 → 12 / 15`，带 Sparkline）| 封存集余量（`7/10` + 48px Meter）| Token（已用/预算 + Meter）| 最近活动（相对时间）| ⋯（暂停、继续、终止、复制链接）。
- 状态 Badge：已创建 neutral、基线标定中 accent 脉冲、运行中 accent 脉冲、已暂停 attention、求助中 danger、已完成 success、已停止 neutral。暂停原因放 Tooltip。
- 行首 2px 状态色条：求助中 danger；有待审 attention。
- 空状态：图标块 + “还没有调优任务” + 一句说明（“让优化者自动改进你的 Agent，每一轮都经过评测和防作弊检查”）+ “新建任务”主按钮 + “接入自己的 Agent”链接（指向使用指南）。

## 4. 新建任务

右侧 Sheet，用 Steps 分 4 步，每步可返回：

1. **被优化 Agent**：档案 Select（列出 `rsi-agents/` 下的档案，每项显示名称和一句说明；可选“自定义路径”）。代码仓路径（Input）。基线 commit（Input，mono，要求完整 SHA，下方提示 `git rev-parse HEAD`）。
2. **优化者**：档案 Select。每项右侧 Badge：OpenCode + DeepSeek 显示“已实测”；Codex、Claude Code 显示“需登录”“未实测”。选后者时显示 Callout：说明用量无法硬限制，需要显式开启，并给登录命令 CopyField。
3. **题集**：题库路径（默认 `rsi-bank`）。SegmentedControl：小题集（试用）/ 完整。下方显示每个集合的题数和语言分布小表。
4. **目标和预算**：目标通过数、最大迭代数、任务 token 预算。Accordion“高级”：单题 token 预算、优化者每轮 token 上限、噪声带重复次数、封存集查询次数、token 增幅上限。全部有默认值。

底部显示上游模型配置状态（来自 worker 状态接口，只显示是否配置，绝不显示值）。

创建成功后留在 Sheet 里显示：
- attention Callout：“这个令牌只显示这一次”+ CopyField 任务令牌。
- CopyField 启动命令。
- “打开任务”按钮。

校验错误显示在对应 Field 下，用接口返回的具体原因。

## 5. 任务详情

- 页面头：面包屑“自优化 / 任务名”；右侧执行器药丸、“添加指令”secondary、⋯（暂停、继续、调整预算、回退、终止、校验账本）。
- 顶部 Callout（按需，最多一条最重要的）：
  - 求助中：danger，显示优化者给的理由，操作“放宽目标”“给思路”“终止”。
  - 暂停：attention，显示原因（预算耗尽、基础设施异常、对比不完整、人工暂停），操作“调整预算”“继续”。
  - 基线标定中：accent，显示进度（已完成 run / 计划 run）。
- MetricStrip：状态 | 基线通过数 | 最优通过数 | 噪声带 δ | 迭代数 | 封存集余量 Meter | Token Meter | 缓存命中率 Meter。未标定前显示“—”。
- 页签：趋势 | 迭代 | 指令 | 决定记录。

**趋势（默认页签）**
- 主图（高 280px）：横轴迭代序号，纵轴训练集通过数。一条折线；**δ 带**是当前父代分数上下的浅色区间；基线是一条水平虚线并标注。点的样式区分结果：已晋级实心 success、已拒绝空心 danger、挂起实心 attention。悬停卡片：序号、假设、分数、状态、原因（人话）。这张图现有图表组件可能不支持，在 `src/components/rsi/` 里基于 CartesianChart 或自绘 SVG 实现，遵守 3.5 的外观规则。
- 下方小标记行：封存集判定，每个跑过封存集的迭代一个圆点（接受 success / 拒绝 danger）。
- 副图：每轮 token 堆叠柱（被优化 Agent / 优化者 / 审查），用 chart 色板；每轮耗时折线。
- 只有基线时显示说明，不显示空坐标系。

**迭代**
- 表格 + 迭代树：首列用缩进和竖线表达父子关系（回退形成的分支要看得出来）。
- 列：# | 假设（单行截断）| 状态 Badge | 训练（分数 + 相对父代的变化 Chip）| 封存（接受 / 拒绝 / —）| 防线（L0～L5 六个小点，颜色：通过 success、挂起 attention、拒绝 danger、缺失 neutral 空心、未到 border）| Token | 耗时 | 时间。行可点。
- 被拒绝的版本保留显示，不隐藏。

**指令**
- “禁令”和“思路”两组列表，每条：文字、生效轮次、时间。
- 添加表单：SegmentedControl 类型 + 文本框 + 添加。说明一句：“下一轮优化者开始时读取”。禁令能写成规则的提示用户另外加进档案。

**决定记录**
- 时间线：每条决定的时间、操作者（Badge：系统 / 人工）、迭代、结论、理由。
- 顶部“校验账本”按钮，结果显示为 Badge：完整 / 异常（列出问题和行号）。

## 6. 迭代详情

- 页面头：面包屑“自优化 / 任务名 / #3”；右侧按状态显示操作：
  - 挂起：“批准”primary、“拒绝”danger、“重新审查”或“重新评测”（只显示当前挂起原因允许的）。
  - 已晋级：“最终验收”（没跑过时）、“回退到此版本”。
  - 最终验收完成：“采纳”。
  - 已拒绝：“回退到父代”。
- 批准弹 Dialog：列出当前挂起原因，每项一个 Checkbox（必须全部勾选）+ 必填理由。缺失类原因不能批准，提示改用“重新审查”。
- **结论卡片**：VerdictCard 网格，五个条件：防作弊 | 主指标（父代 → 候选，增益 vs δ）| 封存集（通过数 vs 下限）| 稳定题 | Token 增幅。每张显示通过 / 拒绝 / 挂起和人话原因。
- **六层防线**：横向一行六格，每格：L0 隔离、L1 规则、L2 封存、L3 对抗、L4 监控、L5 校准，状态图标 + 一句结论。点击跳到相关证据。
- 页签：方案 | 改动 | 发现 | 逐题 | 对抗和消融 | 优化者过程。

**方案**：PRD 的观察、假设、改动范围、预期影响，用 KeyValue。元信息：commit（CopyField）、父代、包 sha256、质量指标（改动行数、文件数）。

**改动**：平台算出的 diff。左侧文件列表（可折叠，移动端变成 Select），右侧 diff 视图。**L1 和监控命中的行高亮**，行尾有小标记，点击显示发现详情。基于 `src/components/trajectory/renderers/edit.tsx` 抽出可复用的 diff 组件。大 diff 虚拟滚动或分文件加载。

**发现**：按层级分组的列表。每条：严重度 Badge、来源 Badge（规则 / 监控 / 过程监控 / 校准 / 人工）、人话类别、证据（代码行 mono）、跳到 diff。监控降级时显示“只告警”Badge。过程监控的结论标注“仅供参考，不影响判定”。

**逐题**：表格：题目 | 集合（smoke / train / sealed）| 语言 | 结果 Badge（通过 / 失败 / 基础设施异常）| 失败原因 | Token | 耗时 | 内存峰值 | 轨迹。点“轨迹”打开右侧 Sheet。

**轨迹 Sheet**：显示代理记录的对话：系统和用户消息折叠，assistant 文本、工具调用逐步显示，每步 token 和缓存命中。这是所有 Agent 都有的通用轨迹。会话库存在时额外显示“会话库 token”对账。分页加载，截断时明确提示。

**对抗和消融**：有效变体表（题目、父代结果、候选结果、是否回归）+ 被丢弃变体的数量和原因；消融结果（撤销了哪些块、分数变化、结论）。没跑时说明原因（比如“没有可疑改动，未触发消融”）。

**优化者过程**：这一轮优化者会话的时长、token、提交结果，以及同样的轨迹视图。声明卡住时显示理由。

## 7. 待审队列

- 表格：任务 | 迭代 | 类型 Badge（挂起 / 随机抽检 / 校准注入）| 原因 Badge | 等待时间 | 假设。行可点进迭代详情。
- 顶部 SegmentedControl：全部 | 挂起 | 抽检。
- 空状态：“没有待处理的审查”+ 一句“系统通过的迭代中会随机抽一部分让你检查”。

## 8. 监控校准

- 任务 Select。
- StatCard 行：监控模式（挂起 / 只告警 / 未校准）| 样本数 | 检出率 | 误报率，带模型和提示词版本。
- **样本不足时**：attention Callout 写明“样本不足，不能说明监控达标”，检出率和误报率仍显示但标“参考”。绝不能看起来像通过。
- 表格：类别 | 样本 | 检出率（含 95% 区间的小条，门槛线 80%）| 确定性规则结果 | 说明。L0、L1 那几类旁边 ⓘ 说明“规则本来就查这些指纹，这个 100% 不代表能抓住现实中的作弊”。
- 良性一行显示误报率（门槛 10%）。
- 没有校准记录时 EmptyState + 启动命令 CopyField。校准只能通过 CLI 启动，页面不触发模型调用。

## 9. 实时和状态

- 用 SSE `rsi_changed` 局部刷新，不闪整页。计时器要清理，组件卸载不能泄漏。
- 所有加载用骨架，错误用 Callout + 重试，接口 401/403 时提示刷新页面。
- 操作提交后 Toast“已加入队列”。worker 没跑时 Toast 里说明要启动执行器。
- 所有写操作都要处理 409（请求冲突），并防止重复点击。
