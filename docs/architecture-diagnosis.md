# 从真实过程证据判断任务边界

任务页的「分析拆分与合并」和「任务模式实验 → 分析真实任务 telemetry」共用一个分析器。
选定任务与成员后，点击按钮才读取本地保留证据；打开页面不自动分析、不启动监控、代理、
Frida、模型或工具，也不会改写提示词。实验报告中的模拟成绩和驱动自报数据不会自动变成
原生会话证据。

## 看什么

报告按「观察事实 → 来源记录 → 调整条件 → 如何复测」组织。三类状态分别是有可检查的
证据、完整覆盖内未观察到、证据不足。后者不等于没有问题。每个发现有原生事件 ID 或
捕获 ID / Codex 逻辑调用序号、原始字段路径，以及最多 240 字符的摘要。点击「定位此
记录」回到任务中的真实事件；捕获可打开本地详情；Codex 调用可打开对应序号的原始
分析。记录、工具声明、模型提议和实际工具结果分别保留身份，不混为一次执行。

报告显示已检查记录数、任务总数、捕获数、逻辑调用数、省略和覆盖限制。它是一次明确
范围的检查，不能给整个任务开“无问题证明”。切换任务、成员或阅读范围、刷新、收到
相关来源变更提示时旧结论清除，需要重新分析。切换语言不重新读取正文。

## 三类分析

| 分析 | 真实依据 | 可以说明什么 | 调整方式 |
|---|---|---|---|
| 上下文膨胀 | 同一明确流中至少 3 个同口径的输入 Token，或完整请求的字符数；完整内容分块哈希；实际工具目录 | 输入增长、可见内容重复携带、工具目录规模；不证明内容无用或质量下降 | 先按需提供历史、工具和技能。独立调查、临时工具输出且只需回传明确交付物时，尝试拆子 Agent |
| 工具选择冲突 | 同一完整请求中的同名异 Schema；实际模型提议与完整目录、tool choice、必填参数；实际结果中的明确契约错误码 | 工具声明或调用约束不一致。提议不代表已执行；一般失败、权限错误、工具使用频率不代表选择错误 | 先修工具名称、Schema、参数与运行时注册；修复后仍有不同专长工具相互干扰，再实验隔离工具集 |
| 交接信息缺口 | 实际发送 / spawn 调用、显式目标身份、完整接收输入；明确要求引用或保守字面锚点 | 接收记录没有原样出现哪些引用；转述、其他上下文或渠道仍可能保留含义，不确证语义丢失 | 先核对交付物和双方原文，增加引用清单 / 接收确认；反复依赖共享中间状态的细碎步骤可尝试合回主循环 |

输入 Token 只接受明确的单次请求用量或原生 `last_token_usage`；会话累计 Token 不是
上下文窗口大小。Anthropic 的输入与缓存口径按现有协议分析器处理。HTTP 只有任务
关联而没有明确连续身份时，不跨捕获比较输入增长。Codex WebSocket 必须使用逻辑
模型调用，不能把整个连接的时长、预览和用量当作一次调用。带 `previous_response_id`
的增量请求正文不是完整上下文，字符比较保持部分覆盖。

工具 namespace 递归展开后再检查；存在不能完整解释的内置工具 / 目录时，不推断
“模型调用未声明工具”。声明了 `send_message` 或存在父子关系，不等于真的发过消息。
当前原生可识别实际函数 / 自定义工具调用及其精确 `call_id` 结果；spawn 目标还需唯一
身份、父子一致、成功结果与完整初始接收输入。普通发送缺少可验证的接收关联时保留
未解决，不按时间相近强行配对。缺失或截断接收正文时，不运行“引用丢失”判断。

## 什么时候拆、什么时候合

拆分适合有独立输入、清晰交付物、可独立验收且历史可在交付后丢弃的分支。先通过
证据确认增长来自哪个调查或输出，再约定子 Agent 返回的结论、依据、文件和未解决项。
不能因为输入变大就把仍依赖连续中间推理的工作拆开。重复携带必要约束很常见，应先
检查按需取回能力和缓存，而不是删除约束。

合回适合严格顺序依赖、反复传递相同中间状态、接收方必须重建细节才能继续的步骤。
同一对 Agent，或同一发送方向多个接收方的完整、显式交接中反复出现引用缺口时，
报告会建议检查边界并有条件实验合回；交接次数与子 Agent 数量本身不证明步骤耦合。
报告中的引用缺口只是检查该边界的线索；先验证是否真的影响后续决策，再尝试合并。
独立审查 / 结果验证可以继续保留。没有接收证据时应先补齐 telemetry，不能直接判定
多 Agent 失败或推荐自动合并。

对比实验固定同一任务、模型、工具和成功标准，保存改动前后逐轮 telemetry，比较
输入规模、重试、实际工具错误、交接引用与中间步骤，再检验结果质量。最终通过率、
总成本和总耗时用于验收，但不能替代这些过程证据。系统只给有条件建议，不自动改
架构、提示词或回放任务。

## 默认筛选阈值

这些是产品启发式筛选条件，可在折叠的「分析阈值」里调整，不是文章作者或模型供应商
保证的架构优劣公式。修改后需显式重新分析；报告保留本次使用的阈值。

| 参数 | 默认 | 含义 |
|---|---:|---|
| minSamples | 3 | 同流同口径最少样本 |
| minContextTokens | 32000 | 增长后的输入 Token 下限 |
| minContextChars | 32768 | 完整输入字符下限 |
| growthRatio | 2 | 首末输入增长倍数 |
| duplicateRatio | 0.6 | 可见完整分块重复携带比例 |
| toolCatalogLimit | 32 | 检查较大目录的工具数量 |
| repeatedToolErrors | 2 | 已确认同一 Agent 的独立契约错误次数 |
| minHandoffAnchors | 2 | 自由文本中至少可检查的字面引用数 |

默认最多检查 400 条原生元数据、64 条各不超过 64KiB 的原生正文、8 个捕获、32 个
逻辑调用 / 交接、512 个证据引用；报告最多 64 项发现和 512KiB，每页 20 项。超限
明确列出省略。HTTP 原始正文沿用 2MiB 解码 / 完整性上限；不会用损坏原文的预览
替代证据。Codex 连接在共享有界 worker 中一次解析，避免逐调用反复解析连接。
逻辑调用的请求和响应事件分别限制 64KiB，内部投影最多 4MiB；超过上限的调用保持
部分覆盖，不能据截断正文判断引用缺失。

浏览器分析等待 50 秒，可取消和重试；服务端最长 45 秒，断开连接或关闭服务会取消
其拥有的任务并丢弃迟到结果。本地只读取消不会启动其他工作。原文已删除、来源绑定
改变或读取期间数据变化会拒绝旧结果。导入来源暂不支持验证原生证据时明确显示不可用。

接口和实现范围见 [architecture-diagnosis contract](../openspec/contracts/architecture-diagnosis.md)
及 [spec](../openspec/specs/architecture-diagnosis/spec.md)。无需新增数据库表或运行时依赖。

## 现有会话为什么可能暂时无法判断

本地日志能保留实际工具调用和部分子 Agent 元数据，但未必保留每次模型请求的完整
输入、工具目录、独立用量和接收方消息。分析器不会用会话累计 Token、助手正文长度
或父子关系填补这些缺失。Claude 的分块原始事件如果没有完整消息信封，也不会被
还原成虚构的模型请求；同一 message.id 的多个副本只计一次用量。

要检查完整上下文和工具选择，需要保留原始 HTTP / Codex WS 请求与响应，并确认它们
与目标任务的关联。要核查交接，还需要实际发送调用、返回身份和接收方输入。代理
只是获取这些 telemetry 的方式之一；当前诊断读取可验证的原生事件、已关联 HTTP
捕获与 Codex WS 逻辑调用，其他导入 / 抓取格式不会自动升级成这些证据。默认仍关闭
所有采集，历史缺口不会因打开分析页而自动补齐。大任务达到检查上限时，可以在任务页
选择具体成员，缩小范围再检查。
