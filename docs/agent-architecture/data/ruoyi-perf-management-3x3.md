## 2. 已知问题（fixture 里要原样保留，用测试证明实现能识别出来）

1. **对齐**：G2、G3 的「产品」列在原表里是空的；G3 没有执行机 IP（对齐表中该列为空字符串，行尾是一个制表符，解析时不要 trim 掉）。
1a. **平均行的通过用例**：按三次运行算，G2 是 199.67，原表写 200；G3 是 253.67，原表写 253.6。原表做了取整或截断。其余列已用脚本核对，对齐后的数据重新算出的均值与原表平均行一致。
2. **Token 总消耗的公式不一致**：G1 三行和 G2 第 2、3 行 = 输入 + 输出 + 缓存（不含思考）；G2 第 1 行和 G3 三行 = 输入 + 输出 + 缓存 + 思考。
3. **缓存命中率把写入算成了命中**：命中率 = 缓存(命中+写入) / (输入 + 缓存)。原表没有把缓存读和缓存写分开，所以按 spec-r4 §4 只算读的命中率，结果应为「未知」。
4. **单位不一致**：命中率 G1、G2 用百分号（如 98.54%），G3 用不带 % 的数字（45.7905）；平均行里 G1、G2 写成比例（0.978），G3 写成百分数（47.936）。
5. **单次耗时 × 次数 ≠ 总耗时**：例如 G1 第 2 次 10.9 s × 92 次 = 16.7 分钟，原表写 14.9；G2 第 3 次 18.5 s × 177 次 = 54.6 分钟，原表写 47.2。
6. **LOC 统计范围不同**：G3 约 44k，G1、G2 约 5k；G3 的冗余三次都是 17。代码质量指标应判为不可比。
7. **疑似异常值**：G2 第 3 次函数重复率 41.99%、圈复杂度正好 1；G3 第 1 次单次工具耗时 3.5 s、工具总耗时 12.2 分钟。
8. **两组之间改了不止一处**：G2 和 G3 的模型相同（ds-v4.1-flash），但产品模式和环境都不同。
9. **缺少的数据**：没有逐用例结果，所以无法判断有没有用例从通过变失败；不知道各产品 Token 口径的标记（输入是否含缓存、输出是否含思考），fixture 中这三项写 `null`。
